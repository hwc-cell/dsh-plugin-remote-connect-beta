# 共享出口（relay）：让别人"装完就能用"

> 这份文档写给要改这段代码的人（包括 AI）。它解释**为什么**这么设计，不只是做了什么。
>
> 状态：**M1–M5 全部落地** —— 身份服务、双工隧道、插件第 4 个出口引擎、出口部署、文档。
> **默认走官方出口（见 §7）**；自带服务器那条路照旧保留给不愿意把机器交给出口的人。

## 1. 要解决的问题

原来的形态是"自带服务器"：使用者得有 VPS + 域名 + DNS + nginx + 证书，`docs/self-host` 里那套下来约 8 步。
对"我朋友想用一下"这个场景，门槛高到不成立。

所以要有一条**共享出口**：出口由一方托管，别人只需要装插件 —— 不改域名、不注册账号、不配服务器。

—— 这条与 README 里"作者不托管、不中转"的旧口径**冲突**，那句话已经改掉。现在的口径是：
**默认走共享出口，默认出口由项目作者托管**（地址见 §7），同时保留自带服务器这条更硬的路
（不信任出口的人应该走自建）。

## 2. 拓扑

```
浏览器  →  https://<名字>.dsh.example.com   (出口 nginx，TLS 在这里终止)
              │
              ├── /relay/*  →  身份服务（签发口令、登记名字）
              └── 其它路径  →  127.0.0.1:<relayPort> → 隧道 ──┐
                                                              │  （插件拨出去的长连接）
                                                              ▼
                                              插件（跑 Harness 那台机器）
                                                → 127.0.0.1:8788 → 本机 Harness
```

关键点：**连接永远是插件往外拨**，对方一个入站端口都不开；出口只负责"把某个名字的请求喂给那条连接"。

## 3. 口令归谁（这是这次改动最核心的一条）

旧模型：口令由**跑 Harness 的机器**生成并校验，出口看不到它。

新模型（M1 起）：**口令由出口签发**，理由有三条 ——

1. 多人共用一个出口时，"口令全局唯一"需要一个全局权威；`lib/core/keypool.js` 只能保证**一台机器内**唯一。
2. "口令要合规"（长度/字符集）由签发方一次做对，比在每个客户端上各校验一遍可靠。
3. 出口要能**吊销**某个人的访问，就必须有一份登记表。

**但出口不保管口令。** 身份服务落盘的只有：

- `keyFingerprint` = `sha256(口令)` 的前 16 位；
- 以及每个名字的**退休指纹**（换掉的旧口令），保证旧值永远不会再被发出去。

也就是说：拿到那份状态文件的人**无法还原任何一把能用的口令**，只能看到"有几个人、各自叫什么、什么时候换过"。
代价必须说清楚：**签发那一刻，服务进程见过明文口令。** 想连这一瞬间都不信，只能自己看代码（这也是出口服务放在本仓库里的原因）。

名字（子域）的唯一性由**签发时**保证；口令与名字是一对一。

## 4. 风险 —— 必须在 README 里写清楚

| 谁 | 能看到什么 | 能不能改内容 |
| --- | --- | --- |
| **出口管理员**（托管出口的那个人） | 经过出口的**全部明文流量**（HTTP 头、请求体、响应体）；如果 `?k=` 出现在 query 里，也能看到它 | **能** —— 它在链路中间，改内容是它一句话的事 |
| 出口管理员，看得到别人的口令吗 | 看不到，除非在**签发那一刻**被记录。日常流量里只有指纹 | — |
| 网络上的其他人 | TLS 到出口为止，看不到 | 不能 |
| 插件所在机器上的其他用户 | 能连 `127.0.0.1:8788`（回环裸奔），绕过 TLS | 能（本机） |

**一句话结论**：走共享出口 = **把"你的机器"交给出口管理员**。这是形态决定的，不是实现缺陷。
所以：

- 出口服务**必须开源可审计**（就在本仓库），别人能自己核对；
- 文档里不许写"端到端加密"之类的漂亮话；
- 不想信出口的人，走 `docs/self-host` 那条自建路 —— 那条路不存在这个问题。

邀请码是**入口凭证**，泄漏了等于"别人可以拿它占一个名字"。所以：一次性、有有效期、可以作废。

| 阶段 | 内容 | 状态 |

## 6. 部署（M4 时要跑的命令，先记着）

```bash
# 出口身份服务（1 核 1G 够用，这是个纯转发 + 签发的小进程）
node relay/server.mjs --state /var/lib/dsh-relay/state.json --port 8790
node relay/server.mjs --state /var/lib/dsh-relay/state.json --new-invite   # 发一个邀请码
node relay/server.mjs --state /var/lib/dsh-relay/state.json --list         # 看登记表（不含口令）

# nginx：通配子域 → 本机身份服务 / 隧道端口
#   证书先给要用的子域逐名签（HTTP-01），不依赖 DNS-01
```

使用者拿到的是一条命令：

```bash
npx dsh-plugin-remote-connect-beta serve --relay --invite <邀请码>          # 官方出口（默认）
npx dsh-plugin-remote-connect-beta serve --relay https://my-exit.example.com --invite <邀请码>
# → https://<名字>.<出口域名>/?k=<口令>
```

他自己不用改域名、不用注册、不用装客户端。

## 7. 官方出口（默认）—— 全仓库唯一出现真实地址的地方

**默认出口 = 官方出口**，不填 `public.relay.url` 时自动用它。地址只写在
`lib/core/officialExit.js` 一个文件里：

```js
export const OFFICIAL_EXIT_URL = 'https://relay.dsh.lycheeledger.cn'
```

为什么它可以进公开仓库：它是**公开的产品端点**（性质同 ngrok.com / trycloudflare.com），不是私有值。
门禁 `test/no-private-values.sh` 因此对 `dsh.lycheeledger.cn` 这一个子域单独放行 ——
注意放行是**精确**的：门禁把官方这个主机名抠掉之后会再判一次，所以**同域名的任何其它子域**
（只要不是 `dsh` 那个）照旧算泄漏，服务器 IP / 私钥 / 本机路径也一律照抓。

**默认 ≠ 唯一。** 换出口有两条路，都不用改代码：

| 写法 | 结果 |
| --- | --- |
| `--relay`（不带值）/ `--tunnel relay` / 配置里 url 留空 | 官方出口 |
| `--relay official` / `--relay default` | 官方出口（显式写法） |
| `--relay https://your-exit.example.com` | 你自己的出口 |
| 配置 `public.relay.url: https://your-exit.example.com` | 同上一行 |

**面板必须把「官方出口」标出来**（`relay.exitOfficial`）—— 默认出口是作者的机器，用户有权知道自己在信任谁，
不能默默替他用。改这块时别把这个标记删掉，`test/verify.mjs` 有断言守着。

把自己搭的出口给别人用（自建出口）：出口服务就在本仓库 `relay/server.mjs`，
部署步骤见 §6；把地址发给你要邀请的人即可。

### 在面板上换出口（那一栏默认就填着官方出口）

面板里「出口地址」**默认填着官方出口**，可以直接改成别人的：

| 你在面板里填的 | 结果 |
| --- | --- |
| 官方出口地址（默认，不动它）/ 留空 / `official` / `default` | 官方出口 |
| 别人的出口地址（可以不写 `https://`） | 换成别人的，**立刻**按新出口重拨隧道（链接会短暂断开） |

- 旁边那个**邀请码**框：换到别人的出口时填那边给你的邀请码（一次性）。没有它登记不上，也就拨不上隧道；
  已经登记过的出口永远不用再填。出口换了，旧出口签发的访问口令在新出口上作废 —— 面板会按新出口重新登记，
  换回原出口时盘上那份旧凭据会被捡回来复用。
- 换出口写的是**状态文件**（`$DSH_HOME/remote-connect/relay-exit.json`，0600），**不用**改你的
  `cordis.patch.yml`：配置里那个 `url` 只是种子，运行时的真值在状态文件里（与访问口令同一条规矩）。
- 那一栏**不做任何隐藏默认**：默认出口是作者的机器，你有权知道自己在信任谁，所以官方出口永远被显式标出。
- 接口上这是一条**新增**路由 `POST /remote-connect/api/relay`（body `{url, invite?}`，仅宿主窗口可调），
  其余接口与响应结构没动。
